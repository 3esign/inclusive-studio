# Where the work lives

Checked 2 October 2026. The studio has no course accounts, private submission server or Drive connection. The official weekly record is physical: one A3 sheet reviewed in class and signed by the teacher.

| Work | Current location | Who can access it | What preserves it |
|---|---|---|---|
| Weekly course work | Physical A3 sheet | Student and people present at the review | Student keeps the sheet; teacher's signature records the review |
| Published site, reference cards and approved teaching image | Public GitHub repository and GitHub Pages | Everyone | Repository history; local course copy |
| Idea Atelier note, draft text, stage and reading preferences | Browser storage on `https://3esign.github.io` | This browser profile; scripts on the same origin | Download a Markdown, text or editable JSON copy; storage is not guaranteed |
| Selected image/PDF and canvas strokes | Current tab memory | Current tab | Keep the original file; download a sketch as PNG before leaving |
| Text in a submitted issue | GitHub Issues | Everyone | GitHub record; a future course archive/export still needs an owner |
| File attached in the GitHub editor | GitHub attachment storage, not the repository's Git file tree | Public-repository uploads are accessible without sign-in | Keep the original; Git history does not back up these attachments |
| Original association recordings and private interviews | Existing local course archive | Existing local access rules | No originals uploaded by this release |

Files dropped into GitHub's editor upload immediately, before the issue is submitted. A preview on this studio site does not upload anything. GitHub documents separate limits: images 10 MB, other files 25 MB; video limits depend on the account plan. This studio deliberately previews only PNG/JPEG/PDF up to 10 MB. [GitHub attachment documentation](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files).

## Sign-in and optional public handoff

Reading, preparing, printing and downloading need no account. Public posting opens `github.com`, where the participant signs in using GitHub's own flow. This is not enrolment in a course, a private student workspace, attendance or an official submission receipt.

The optional handoff selects the repository's issue form and fills its text field. Labels come from the repository template: the URL does not request label-setting permissions from a participant. A public project reference can include its phase; it is never an official course hand-in. Long drafts need to be downloaded and pasted. The login provider may interrupt or change that flow, so keep a local copy. [GitHub issue URL documentation](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-an-issue).

Only one text draft is retained per browser profile; two tabs can overwrite that stored copy. JSON export/import preserves text, kind and phase. It does not include files, sketches, consent, credentials, grades or other browser settings. Imported text is reviewed before replacing the current draft. Shared computers are not private; download and clear text before leaving.

## Proposed archive for the next step

Keep public discussion on GitHub optional. Once the course owner connects Drive, establish a restricted course folder for originals and a separate reviewed-public selection. Decide ownership, access, retention, withdrawal requests, versioning and backups before opening uploads to participants. A login alone does not establish these rules.

For each published asset, retain an internal record of source, author if known, capture date if known, publication agreement, public derivative, description/transcript and review date. Publish only the derivative and necessary non-personal context. Never place interview records or a private Drive share link in a public issue.

No participant needs GitHub to complete the course flow. The A3 sheet and in-class review are the working record. A future Drive archive, if adopted, must remain a separate course decision with clear access, retention and withdrawal rules.

## Verification limits

Source and link construction were checked; there is no claim that a new participant's entire sign-in, attachment and final posting flow was completed. GitHub's own [accessibility conformance report](https://accessibility.github.com/conformance/github-com/) documents partial support in parts of the platform. A course pilot needs real participant testing and an operational supported route.
